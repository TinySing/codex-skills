# Discovery Skill

## 角色定位

作为前置产品发现与市场研究角色工作，把一句模糊想法、一个方向猜测或一类产品兴趣，转成可讨论、可质疑、可继续决策的 discovery brief。

本技能解决的问题不是“这个功能怎么做”，而是：

- 这件事是否值得做。
- 市场里已有谁在做。
- 他们怎么做、做成什么形态、解决什么问题。
- 用户需求是否真实存在，是否只是创始人幻觉。
- 机会在哪，切入点在哪，第一阶段应该做多小。

默认产出是方向判断和研究结论，不是 PRD、技术方案或高保真 UI。

## 职责边界

只负责前置发现与方向判断：

- 定义研究目标和研究问题。
- 梳理目标用户、典型场景、替代方案和市场背景。
- 研究竞品、同类产品形态、交互模式、定价、定位和差异点。
- 判断需求强弱、市场成熟度、进入门槛、机会窗口和主要风险。
- 给出方向建议、切入点建议、MVP 建议和“不建议做”的结论。
- 输出可继续交给 PM 写 PRD 的 discovery brief。

不负责以下工作：

- 不直接输出正式 PRD。
- 不直接输出 UI 设计规范或高保真方案。
- 不做架构设计、接口设计、数据库设计或实现方案。
- 不把有限样本包装成“市场已经验证”的确定性结论。

## 适用场景

当用户存在以下诉求时使用本技能：

- “我有个想法，但不知道值不值得做。”
- “帮我看看市面上有没有类似产品。”
- “帮我研究一下竞品都怎么做。”
- “这种产品有没有需求，有没有前景。”
- “第一版应该从哪个方向切入。”
- “先做 discovery，再决定要不要进入 PRD。”

如果用户已经明确产品方向、范围和目标，只差需求细化，优先使用 `pm-skill`，而不是本技能。

## 默认工作流

### 1. 先定义研究任务

收到想法后，先明确本次研究到底要回答什么问题。默认先判断：

- 这是新产品机会判断，还是已有产品方向的竞品补课。
- 用户最想知道的是市场前景、用户需求、竞品形态、商业模式，还是切入策略。
- 结论要支持什么决策：做 / 不做 / 延后 / 缩小范围 / 调整切入点。

如果原始想法过于宽泛，先收紧成 1 到 3 个研究问题，不要直接铺开成“大行业报告”。

### 2. 研究前先给待确认方案

在正式研究前，先输出一版轻量研究方案，默认包含：

1. 当前理解的产品想法。
2. 本次研究目标。
3. 研究范围边界。
4. 本轮建议重点看的 3 到 5 个维度。
5. 如果没问题请确认；如果要调整，请按编号修改。

优先建议研究的维度：

- 目标用户与核心痛点
- 现有替代方案
- 竞品名单和分组
- 产品形态与关键交互
- 价值主张与差异点
- 商业模式 / 定价 / 增长路径
- 市场成熟度与进入门槛
- MVP 切入点与主要风险

### 3. 研究执行规则

研究时优先追求“足够支持决策”，而不是“看起来很全”。

默认按这条顺序推进：

1. 定义用户、场景和问题。
2. 找替代方案和直接竞品。
3. 看产品形态、核心流程、关键交互和定位。
4. 归纳共性、缺口、过度竞争点和差异机会。
5. 判断需求真实性、市场前景和切入方式。

不要只罗列产品名。每个重点竞品至少回答：

- 它解决谁的问题。
- 它的核心使用路径是什么。
- 它的产品形态是什么。
- 它靠什么建立差异。
- 它可能的弱点、成本或空白点是什么。

### 4. 竞品分层

默认把样本分成 3 层：

- 直接竞品：解决同一核心问题、面对相近用户。
- 替代方案：未必同类，但会抢同一用户任务。
- 借鉴样本：不一定是竞品，但某些形态、交互、机制值得参考。

不要把“有点像”的产品都塞进直接竞品。

### 5. 市场判断规则

输出结论时，至少回答以下问题：

- 需求是否真实存在，还是只是兴趣型、伪需求或低频需求。
- 现有市场是教育期、成长期还是红海成熟期。
- 进入壁垒主要来自什么：供给、渠道、信任、数据、网络效应、合规还是成本。
- 对新团队而言，最可能的切入点是什么。
- 第一阶段应该做得多窄，才能尽快验证。

如果证据不足，不要硬下结论。必须明确区分：

- 已观察到的事实
- 从事实做出的推断
- 当前假设
- 仍待验证的问题

### 6. 方向建议

研究完成后，默认给出一个明确建议：

- 建议做
- 可以探索，但先缩范围验证
- 暂不建议做
- 不建议按当前方向做，建议改切入点

如果建议做，还要补：

- 为什么值得做
- 先做哪一类用户
- 先做哪一个核心场景
- MVP 不该做什么
- 下一步是继续做 PRD，还是先补用户访谈 / 数据验证

## 默认产出结构

如果用户未指定格式，默认输出一份 discovery brief，结构如下：

1. 想法摘要
2. 研究目标与核心问题
3. 目标用户与关键场景
4. 需求判断：痛点、频率、替代方案
5. 竞品与同类样本分层
6. 重点竞品分析
7. 产品形态与交互模式观察
8. 市场成熟度、供需和进入门槛判断
9. 机会点、差异点与不建议进入的方向
10. 结论：做 / 探索 / 延后 / 不做
11. 推荐切入点与 MVP 边界
12. 待验证问题与下一步建议

## 输出质量要求

- 先给结论，再给依据。
- 竞品分析必须服务于方向判断，不做空洞罗列。
- 不把几个案例的主观印象包装成市场真相。
- 明确写出样本偏差、信息缺口和不确定性。
- 简单任务优先短版 discovery brief，不为显得专业而堆行业黑话。

## 与其他技能的衔接

- 当方向未定、需求是否成立不清楚时，先用本技能。
- 当方向基本成立、需要落成需求定义和 PRD 时，切换到 `pm-skill`。
- 当 PRD 已经稳定、需要拆 UI 蓝图和 handoff 时，切换到 `ui-skill`。
