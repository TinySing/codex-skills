# BE Skill 输出参考

## 后端咨询

- 结论
- 原因
- 建议
- 有不确定点时直接说明
- 必要时向用户确认，或给出明确推荐并标注为推荐

## 后端实施方案

- 实现决策
- 服务、契约、数据、一致性、权限、集成边界
- 复用点、第三方方案和不建议自研的部分
- 实施顺序与关键调用流程
- 验证方式与交付说明

## API 契约

涉及前端联调时必须提供字段级 API 契约。

- 小功能、接口少：内嵌在 `backend-plan.md`
- 多页面、多接口、多人并行、前端要独立开发：额外输出 `api-contract.md`
- 不涉及前端或跨服务消费：不强制产出 API 文档

`api-contract.md` 最低结构：

- API 列表：method、path、用途、页面/场景
- 鉴权与权限：auth、permission、数据范围
- 请求契约：params、query、body、字段类型、必填、默认值、校验规则
- 响应契约：success response、分页、状态枚举、空结果语义
- 错误语义：error code、message、前端展示建议、可重试性
- 幂等与并发：重复提交、状态流转、冲突处理
- 联调说明：mock 数据、调用顺序、验收用例

可展开的后端细节：

- HTTP API 字段级契约
  - method / path
  - auth / permission
  - params / query / body
  - success response
  - error codes
  - 幂等和重复提交规则
- WebSocket / 事件 / 队列契约
  - event name
  - direction
  - payload
  - ack / retry
  - 幂等规则
- DTO、校验规则、错误语义
- 数据模型
  - 表、字段类型、必填、默认值
  - 主键、唯一索引、普通索引
  - 状态枚举和状态机
  - 外键或逻辑关联
  - migration、seed、回滚
- 事务、一致性、幂等、并发控制
- 缓存、限流、任务、文件存储
- 安全、审计、可观测性
- 测试：单元、集成、契约、联调
- 部署、发布、回滚

输出要求：

- 不复述 PRD、架构文档已经明确的目标、范围、背景和现状
- 只有上游信息缺失、冲突或影响实现时，才增加很短的“输入校准”段
- 默认只写一个推荐方案，不写“可选两种路线”“方案 A / 方案 B”
- 默认不写“待确认项”“阻塞项”“风险说明”，除非确实存在且会阻断实现
- 重点写服务边界、接口契约、数据模型、一致性、复用点、实施顺序和验证方式
- 前端对接需要字段级 API 契约；接口多时拆 `api-contract.md`
- 以上约束只用于生成 `backend-plan.md`，不用于问题修复、排障、实现修改或日常问答
