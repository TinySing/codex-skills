# FE Skill 输出参考

## 简单问题

- 直接给结论
- 直接给原因
- 直接给建议
- 有不确定点时直接说明
- 必要时向用户确认，或给出明确推荐并标注为推荐

不要补“适用场景 / 不适用场景 / 常见误区 / 示例”这类非必要说明，除非用户明确要求。

## `frontend-plan.md`

- 实现决策
- 页面、组件、状态、样式边界
- 接口依赖与联调约束
- 复用点、第三方方案和不建议自研的部分
- 实施顺序与页面交互流程
- 验证方式与交付说明

输出要求：

- 不复述 PRD、UI、架构文档已经明确的目标、范围、背景和现状
- 只有上游信息缺失、冲突或影响实现时，才增加很短的“输入校准”段
- 默认只写一个推荐方案，不写“可选两种路线”“方案 A / 方案 B”
- 默认不写“待确认项”“阻塞项”“风险说明”，除非确实存在且会阻断实现
- 重点写实现流程、模块拆分、状态流、接口依赖、复用点和验证方式
- 控制篇幅，删除不能直接指导实现的铺垫性内容
- 以上约束只用于生成 `frontend-plan.md`，不用于问题修复、排障、实现修改或日常问答
