# Golden PRD Example

这是 `pm-skill` 的质量标尺示例，不是固定模板。真实任务应按复杂度裁剪，但正式 PRD 至少要达到这里体现的几个标准：

- 产品目标清楚
- 第一阶段范围收敛
- 业务对象和状态清楚
- 页面 / 模块足够 UI 承接
- 业务规则足够架构和研发继续拆解
- P0 需求可验证
- 下游交接输入明确

# PRD：客户跟进工作台 MVP

## 1. 文档信息

- 文档版本：v1.0
- 适用阶段：MVP
- 产品负责人：PM
- 目标上线范围：销售团队内部试点

## 2. 背景、问题定义和产品目标

中小销售团队通常通过表格、聊天工具和个人备忘录跟进客户，客户状态、下一步动作和负责人信息分散，导致主管无法判断客户推进情况，销售也容易遗漏关键跟进节点。

本阶段目标是提供一个轻量客户跟进工作台，让销售能集中管理客户、记录跟进行为、明确下一步动作，并让主管能快速识别停滞客户。

## 3. 成功指标

- 试点团队 80% 销售在上线后一周内创建或认领至少 10 个客户。
- 试点团队中，客户记录的下一步动作填写率达到 70%。
- 主管每周能通过工作台识别停滞超过 7 天的客户。
- 销售反馈“漏跟进”场景明显减少，试点期内收集定性反馈。

## 4. 关键产品决策与规划前提

- 首版只做销售团队内部客户跟进，不做市场获客、合同、回款和售后。
- 首版以 Web 工作台为主，优先保证信息录入、检索和状态识别效率。
- 客户状态采用固定枚举，避免首版引入复杂自定义流程。
- 跟进记录只记录业务动作和结果，不做完整 CRM 自动化。
- 主管角色只查看团队范围数据，不做跨团队组织管理。

## 5. 范围、非目标和优先级

### In Scope

- 客户列表
- 客户详情
- 新增 / 编辑客户
- 客户状态管理
- 跟进记录
- 下一步动作
- 停滞客户提示
- 销售和主管两类角色

### Out of Scope

- 商机金额预测
- 合同和回款管理
- 客户导入导出
- 自动提醒通知
- 自定义销售流程
- 移动端适配专项
- 第三方 CRM 集成

### 优先级

- P0：客户管理、状态管理、跟进记录、下一步动作、停滞识别、基础权限。
- P1：列表筛选增强、主管视图统计、批量操作。
- P2：自动提醒、导入导出、销售流程配置。

## 6. 目标用户、角色和使用前提

### 目标用户

- 一线销售：负责创建、维护和推进客户。
- 销售主管：负责查看团队客户推进情况，识别停滞客户。

### 角色权限

| 角色 | 权限范围 | 关键限制 |
|---|---|---|
| 销售 | 查看和编辑自己负责的客户 | 不能查看他人客户详情 |
| 主管 | 查看团队客户列表和详情 | 不能编辑销售的跟进记录正文 |

### 使用前提

- 用户已属于一个销售团队。
- 每个客户必须有唯一负责人。
- 每个客户必须处于一个业务状态。

## 7. 业务对象、核心状态和长期业务规则

### 业务对象

| 对象 | 含义 | 关键字段语义 |
|---|---|---|
| 客户 | 被销售跟进的公司或个人 | 名称、联系人、负责人、状态、下一步动作、最近跟进时间 |
| 跟进记录 | 销售对客户的一次业务接触 | 跟进方式、内容摘要、结果、创建人、创建时间 |
| 下一步动作 | 销售计划对客户执行的后续动作 | 动作内容、计划日期、负责人 |

### 客户状态

| 状态 | 含义 | 可进入条件 |
|---|---|---|
| 新客户 | 已录入但尚未有效沟通 | 新建客户默认状态 |
| 跟进中 | 已发生有效沟通，仍在推进 | 至少存在一条有效跟进记录 |
| 暂缓 | 客户当前无明确推进动作 | 销售主动选择并填写原因 |
| 已成交 | 客户已完成成交 | 销售选择成交结果 |
| 已流失 | 客户确认不继续推进 | 销售选择流失原因 |

### 长期业务规则

- 客户名称不能为空。
- 客户必须有负责人。
- 客户状态变更必须保留最近一次变更时间。
- 已成交和已流失客户仍可查看历史跟进记录。
- 已成交和已流失客户不再进入停滞客户列表。
- 跟进记录创建后不允许删除，可追加更正记录。

## 8. 核心场景和关键任务路径

### 场景 A：销售新增客户并计划跟进

1. 销售进入客户列表。
2. 点击新增客户。
3. 填写客户名称、联系人、联系方式和下一步动作。
4. 系统创建客户，状态为新客户。
5. 客户出现在销售自己的客户列表。

### 场景 B：销售记录一次跟进

1. 销售进入客户详情。
2. 点击添加跟进记录。
3. 选择跟进方式，填写内容摘要和结果。
4. 可同时更新客户状态和下一步动作。
5. 系统保存记录，并更新最近跟进时间。

### 场景 C：主管查看停滞客户

1. 主管进入客户列表。
2. 切换到停滞客户筛选。
3. 查看超过 7 天没有跟进且未成交 / 未流失的客户。
4. 进入客户详情查看负责人、最近记录和下一步动作。

## 9. 页面 / 模块范围和页面地图

| 页面 / 模块 | 页面职责 | 主要用户 | 关键状态 |
|---|---|---|---|
| 客户列表 | 查看、筛选、进入客户 | 销售、主管 | 空列表、加载、筛选无结果、停滞客户 |
| 客户详情 | 查看客户信息、状态、记录和下一步动作 | 销售、主管 | 无记录、已成交、已流失 |
| 新增 / 编辑客户 | 创建或维护客户基础信息 | 销售 | 必填缺失、重复客户提示 |
| 添加跟进记录 | 记录一次客户接触 | 销售 | 内容为空、保存成功、保存失败 |

## 10. 功能需求

### P0-1 客户列表

- 目标：让用户快速查看自己或团队范围内的客户推进情况。
- 对应页面：客户列表。
- 入口：登录后默认进入。
- 前置条件：用户已属于销售团队。
- 主流程：
  1. 用户进入客户列表。
  2. 系统展示客户名称、状态、负责人、下一步动作、最近跟进时间。
  3. 用户可按状态筛选客户。
  4. 用户点击客户进入详情。
- 分支流程：
  - 销售只看到自己负责的客户。
  - 主管看到团队全部客户。
  - 用户选择停滞筛选时，只展示超过 7 天未跟进且未成交 / 未流失的客户。
- 异常处理：
  - 无客户时展示空态，并提供新增客户入口。
  - 筛选无结果时展示筛选空态，可清除筛选。
- 验收标准：
  - 销售不能看到他人客户。
  - 主管能看到团队客户。
  - 停滞筛选结果不包含已成交和已流失客户。

### P0-2 新增客户

- 目标：让销售录入需要跟进的客户。
- 对应页面：新增客户。
- 入口：客户列表的新增入口。
- 前置条件：用户为销售角色或具备客户创建权限。
- 主流程：
  1. 用户点击新增客户。
  2. 填写客户名称、联系人、联系方式、下一步动作。
  3. 提交后系统创建客户。
  4. 新客户进入客户列表，默认状态为新客户。
- 分支流程：
  - 未填写下一步动作时允许保存，但客户会在详情中显示“未设置下一步动作”。
- 异常处理：
  - 客户名称为空时不能提交。
  - 联系方式格式明显不完整时提示用户检查。
  - 存在同名客户时提示用户确认是否继续创建。
- 验收标准：
  - 新建客户必须有负责人。
  - 新建成功后能在客户列表看到。
  - 必填缺失时不会创建客户。

### P0-3 添加跟进记录

- 目标：沉淀销售与客户的关键接触历史。
- 对应页面：客户详情、添加跟进记录。
- 入口：客户详情的添加记录入口。
- 前置条件：用户是客户负责人。
- 主流程：
  1. 用户进入客户详情。
  2. 点击添加跟进记录。
  3. 选择跟进方式，填写内容摘要和结果。
  4. 可更新客户状态和下一步动作。
  5. 提交后记录显示在客户详情中。
- 分支流程：
  - 如果更新状态为暂缓，必须填写暂缓原因。
  - 如果更新状态为已流失，必须填写流失原因。
- 异常处理：
  - 内容摘要为空时不能提交。
  - 保存失败时保留已填写内容，允许重试。
  - 非负责人只能查看记录，不能新增记录。
- 验收标准：
  - 跟进记录创建后不可删除。
  - 添加记录后客户最近跟进时间更新。
  - 状态变更后客户列表同步展示新状态。

### P0-4 停滞客户识别

- 目标：帮助主管识别需要关注的客户。
- 对应页面：客户列表。
- 入口：客户列表筛选项。
- 前置条件：用户为主管角色。
- 主流程：
  1. 主管进入客户列表。
  2. 选择停滞客户筛选。
  3. 系统展示超过 7 天未跟进且未成交 / 未流失的客户。
  4. 主管进入详情查看负责人和最近记录。
- 异常处理：
  - 无停滞客户时展示正向空态。
- 验收标准：
  - 停滞客户计算以最近跟进时间为准。
  - 新客户从创建时间开始计算停滞。
  - 已成交、已流失客户不进入停滞列表。

## 11. 权限边界、状态处理和边界条件

### 权限边界

- 销售只能查看和编辑自己负责的客户。
- 主管能查看团队全部客户。
- 主管不能修改销售已提交的跟进记录正文。
- 非客户负责人不能新增跟进记录。

### 状态处理

- 新建客户默认状态为新客户。
- 添加有效跟进后，销售可将状态更新为跟进中。
- 暂缓、已成交、已流失需要用户明确选择。
- 已成交、已流失客户保留详情和历史记录。

### 边界条件

- 客户没有跟进记录时，详情页展示空态。
- 客户没有下一步动作时，详情页展示提示。
- 重复提交新增客户时，系统不应创建完全重复记录。
- 保存失败时应保留用户已输入内容。

## 12. 验收标准

- 销售能完成新增客户、查看客户、添加跟进记录、更新状态。
- 主管能查看团队客户并筛选停滞客户。
- 销售无法查看非本人客户详情。
- 非负责人无法新增跟进记录。
- 已成交和已流失客户不会出现在停滞客户筛选结果中。
- 所有 P0 页面覆盖加载、空态、错误态、无权限态。

## 13. 下游交接输入

### 给 UI

- 首版核心页面为客户列表、客户详情、新增 / 编辑客户、添加跟进记录。
- 客户列表需要突出状态、负责人、下一步动作和最近跟进时间。
- 客户详情需要突出客户状态、下一步动作和跟进历史。
- 添加跟进记录需要支持保存失败后保留输入。
- 必须覆盖空列表、筛选无结果、无跟进记录、无权限、保存失败状态。

### 给架构

- 核心业务对象为客户、跟进记录、下一步动作。
- 核心状态为新客户、跟进中、暂缓、已成交、已流失。
- 关键不变量：客户必须有负责人；跟进记录创建后不可删除；已成交和已流失客户不进入停滞列表。
- 权限边界以客户负责人和团队主管为基础。
- 停滞识别依赖最近跟进时间或创建时间。

### 给研发

- P0 需要支持客户列表、客户详情、新增客户、添加跟进记录、状态更新、停滞筛选。
- 必须覆盖销售和主管权限差异。
- 必须覆盖保存失败、重复客户提示、无权限访问、筛选无结果。
- 验收以 P0 功能需求和权限边界为准。

## 14. 发布说明和复盘口径

- 上线范围：先对一个销售团队开放。
- 发布方式：内部试点，收集一周使用数据和反馈。
- 成功信号：客户创建率、下一步动作填写率、停滞客户查看情况。
- 失败信号：销售无法持续录入、主管无法识别停滞客户、权限边界造成误看。
- 复盘窗口：上线后 7 天做首轮复盘，30 天判断是否进入 P1。
