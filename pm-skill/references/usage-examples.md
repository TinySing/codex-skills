# PM Skill 调用示例

```text
使用 $pm-skill，我想做一个面向中小团队的协作工具。
```

说明：
此时应先进入需求收敛式澄清模式，直接列出 3 到 5 条带小标题的关键决策建议，让用户确认或按编号修改，而不是直接输出 PRD。

```text
使用 $pm-skill，基于我们刚才确认的规则，输出一版正式 PRD。
```

说明：
此时如果关键信息已完整，可直接产出 PRD，并默认落盘到当前项目目录的 `prd.md`；如果仍缺会影响交付的关键信息，应先继续澄清。

```text
使用 $pm-skill，帮我把这个想法问清楚，最终产出可给 UI 和技术继续拆解的 PRD。
```

说明：
此时先通过带小标题的收敛方案确认定位、用户、范围、流程、规则、状态、异常和验收，再输出正式 PRD。

```text
使用 $pm-skill，基于已确认规则输出完整 PRD，包含页面地图、状态矩阵、验收标准和需求追踪表。
```

说明：
此时输出应保持 PM 边界，只写产品规则和业务边界，不写 UI 视觉方案、技术架构、API 或数据库设计。
复杂 PRD 的质量可参考 `references/golden-prd-example.md`。

```text
使用 $pm-skill，检查这个 PRD 是否足够作为 UI、架构和研发的上游输入，并直接指出要先改哪些地方：/absolute/path/prd.md
```

说明：
此时先做 PRD 交接门槛评审，重点看页面范围、业务对象、角色权限、状态、异常、验收和下游输入是否完整。

```text
使用 $pm-skill，基于刚才确认的内容输出 PRD。
```

说明：
此时如果用户没有指定路径，默认把 PRD 写入当前项目目录的 `prd.md`。

```text
使用 $pm-skill，基于现有信息自由规划，直接给我一版可交付 PRD。
```

说明：
此时可结合现有上下文、通用产品惯例和必要调研补齐前提，但正式 PRD 仍应只输出已收敛的结果。

```text
使用 $pm-skill，帮我评审这份需求有没有问题：/absolute/path/prd.md
```

说明：
此时先读文件，再判断是否合格、是否可交给 UI / 架构 / 研发继续，以及主要缺口。

```text
使用 $pm-skill，先去项目目录里找和这个功能相关的需求文档、会议纪要和页面说明，收敛成一版统一 PRD。
```

说明：
此时先找资料、读资料、合并冲突，再决定是否需要补充提问；不是直接凭空写一份新 PRD。

```text
使用 $pm-skill，帮我优化这份现有 PRD，把模糊表述改成可执行规则，但不要越权写技术方案：/absolute/path/prd.md
```

说明：
此时应进入文档优化模式，优先重组结构、补齐产品定义、删掉技术越界内容，再输出优化后的正式文档。
