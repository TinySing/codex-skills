# T5T Skill 能力清单

本文档用于快速判断 `im-teams-t5t` 能做什么、如何触发，以及有哪些明确限制。完整执行流程和维护细节见 [ARCHITECTURE.md](./ARCHITECTURE.md)。

## 核心能力

| 能力 | 支持内容 | 关键限制 |
|------|----------|----------|
| 生成 T5T | 从周报、会议纪要、项目进展、客户反馈、市场观察、任务清单中提炼工作重点 | 最多 5 条，每条不超过 80 字；无材料时不编造 |
| 优化已有 T5T | 压缩、润色、重排、降噪，保留原始意图 | 不把没有依据的内容包装成成果 |
| 查询可填写周期 | 判断当前是否可以新建 T5T | 最新周期已填写时不继续新建 |
| 新建 T5T | 用户授权后一次调用完成核对与写入 | 写入前必须有用户授权（明确提交意图或一次确认）；抄送人只能使用接口返回值 |
| 一步新建或更新本周（`--update-if-exists`） | 用户**明确要更新已有最新 T5T**时，单次调用内“没填就新建、已填就就地更新” | **会静默覆盖现有内容、不弹冲突**；仅在用户清楚知道已有内容并要替换时用，泛泛“帮我写/写下周”不算，不确定就用 plain `--commit-confirmed` 让 `already_submitted` 冲突浮出来再问 |
| 一步更新最新（edit `--latest`） | 自动定位最新单条→核对→提交，无需先单独查 id | 只作用于最新一条；查无已填写返回 not_found |
| 本地格式预检（`--validate-items`） | 纯本地校验 `--items-json` 格式，不联网、不认证、不提交 | 非必需步骤（提交命令已内置联网前校验） |
| 多周期选择（`period_choice`） | 存在多个可填写周期时列出供用户选，再带 `--report-id` 提交 | 仅一个周期时静默选用，不打扰用户 |
| 浏览最近 T5T | 按页只读查看最近若干条 T5T | 仅浏览，不基于历史列表直接编辑 |
| 查询最新 T5T | 展示最新一条的周期、内容、权限、同组可见和可编辑状态 | 没有记录时返回未找到 |
| 编辑最新 T5T | 修改内容、删除已有抄送人、切换同组可见 | 只编辑最新一条；不可新增或修改抄送人对象 |
| 提交保护 | 提交时脚本实时核对周期、详情与权限 | 确认后内容、权限或周期变化时中断提交；两阶段 dry-run+确认哈希仅开发排查用 |
| 认证复用 | 通过内置认证子模块（`scripts/auth/`）获取并复用认证结果 | t5t 业务侧不定义或改写认证策略 |
| 提交后预览 | 提交成功后返回 T5T 预览链接 | 仅在提交成功后提供 |

## 内容处理能力

- 从多种参考材料中筛选最重要的工作事项。
- 按影响、紧急程度、业务价值或用户指定口径排序。
- 保留关键成绩、下周目标、风险、卡点、客户反馈和市场观察。
- 删除日常同步、例行沟通和没有明确结果的琐碎事项。
- 接受 JSON 数组或内容文件作为脚本输入。
- 提交时固定生成 5 项 `rawContent`，不足部分自动补空字符串。

## 系统操作能力

### 新建

1. 用户授权后一次调用：脚本并行查询可填写周期与历史抄送人。
2. 周期为空（本周已填）时：带 `--update-if-exists` 则用本次内容就地更新（同一进程内完成，免再起 edit）；否则返回 `already_submitted` 冲突详情（不提交），由代理走「对比并更新」流程。
3. 周期可用（本周没填）时组装并提交，返回结果与预览链接；存在多个周期时先返回 `period_choice` 让用户选。

> T5T 填写周期横跨「当前周周四 ~ 下周三」，同一时刻只有一个最新可填写周期；用户说的「本周/下周」都指它。「新建还是更新」由查可填写周期决定，与字面无关。

### 查询与编辑

1. 分页浏览最近 T5T，或查询最新一条详情。
2. 根据 `canOperate` 判断是否允许编辑。
3. 用户授权后一次调用提交内容修改、抄送人删除或同组可见变更；脚本重查详情核对后提交，变化即中断。

## 支持的修改范围

| 修改项 | 新建 | 编辑最新 T5T |
|--------|------|----------------|
| T5T 内容 | 支持 | 支持 |
| 同组可见 | 支持，默认开启 | 支持，不传时保留原值 |
| 抄送人 | 只使用历史抄送人接口返回值 | 只允许删除已有抄送人 |
| 添加抄送人 | 不支持 | 不支持 |
| 编辑历史 T5T | 不适用 | 不支持，仅编辑最新一条 |

## 明确不支持

- 在没有参考材料时生成看似真实的 T5T。
- 一次提交超过 5 条或单条超过 80 字的内容。
- 未经用户授权（明确提交意图或一次确认）直接写入。
- 自行拼接提交 payload。
- 在周期不可填写时继续新建。
- 修改不可操作的 T5T。
- 新增、替换、构造或修改抄送人对象。
- 暴露完整 token、认证请求头或内部环境配置。

## 常见使用方式

- “根据这份周报生成下周 T5T。”
- “把这 5 条压缩并按优先级重排。”
- “看看最近 5 条 T5T。”
- “查询最新 T5T。”
- “把最新 T5T 的第 2 条改成……”
- “删除最新 T5T 中的某个已有抄送人。”
- “将最新 T5T 调整为同组不可见。”
- “确认后把这版 T5T 写入系统。”
